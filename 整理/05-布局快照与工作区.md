# 布局快照与工作区

## LAYOUT-01 吸附与排列

**需求：** 拖动或缩放时可贴齐网格、相邻分区和屏幕边缘；一键排列不覆盖锁定项，不让分区超出工作区。

**建议实现：** 将候选位置计算与实际写入分开。输入工作区、障碍物、分区尺寸、最小间距、优先显示器，输出位置或明确失败；成功后整体提交并记录撤销。拖动吸附提供可见参考线及临时跳过方式。

**验收：** 空间不足保留旧布局；锁定项和组件避让；手动拖动不会马上被自动排列改回；撤销恢复全部位置。

当前入口：[GroupArrangement.cs](../code/src/GroupArrangement.cs)、[Layout.cs](../code/src/Layout.cs)。上游：[SnapManager.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/SnapManager.cs>)、[LayoutManager.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/LayoutManager.cs>)。吸附与自动排列作为同一布局服务的两种调用，避免重复坐标算法。

## LAYOUT-02 多屏与 DPI

**需求：** 插拔显示器、改变缩放或主屏、任务栏位置变化后，分区可触及，正常副屏负坐标保留。

**建议实现：** 保存显示器标识、工作区矩形、DPI 和逻辑坐标。屏幕坐标与 WPF DIP 转换在边界完成；按显示拓扑生成布局档案键。恢复优先匹配原显示器，其次找相交最多的工作区，再回退主屏。越界恢复与主动按比例缩放是两个策略，不应每次重绘都改尺寸。

**验收：** 100%/150% 混合缩放、负坐标副屏、断开副屏再接回、切主屏、任务栏换边、远程连接前后均有明确结果。

当前入口：[Layout.cs](../code/src/Layout.cs)、[Shell.cs](../code/src/Shell.cs)、[Controller.cs](../code/src/Controller.cs)。上游：[LayoutDisplays.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/LayoutDisplays.cs>)、[LayoutModel.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/LayoutModel.cs>)。Fences 的分辨率指纹和相对位置模型见 [布局资料](../references/Fences-4.0.0.3-analysis/features/05-layouts.md)。

## LAYOUT-03 布局模板

**需求：** 新用户可选择右侧、左右、上下等模板，并先预览；模板适应当前分区数量与工作区。

**建议实现：** 使用栖桌自己的 JSON 模板，包含区域相对尺寸、锚点、方向、间距、数量约束。模板计算得到草案，经校验后统一应用；OEM 厂商预置和普通主题模板合并为同一个能力，不增加独立 OEM 产品线。

**验收：** 不同分辨率、0/1/多个分区、锁定分区下可预览；放不下时提示；应用可撤销。

参考：[Fences 布局 XML 分析](../references/Fences-4.0.0.3-analysis/features/05-layouts.md)、[OEM 布局模型](../references/Fences-4.0.0.3-analysis/features/11-oem-layouts.md)。无需照搬 Fences 私有字段或全部兼容其模板格式。

## LAYOUT-04 快照撤销与备份

**需求：** 保存命名快照，预览并恢复布局与配置；自动备份保留有限历史；恢复不误改磁盘文件。

**建议实现：** 区分操作撤销、配置快照和数据备份。操作撤销记录一项事务；快照保存版本化配置和可选缩略图；备份可打包配置、自定义图标、组件清单及应用自建快捷方式。快照不自动包含用户映射目录的实体内容。恢复前校验并生成当前状态的恢复点，原子提交后再重建窗口。

**验收：** 损坏文件、旧版本、部分路径不存在、恢复中失败均不会覆盖可用配置；自动清理只处理本程序生成的自动备份；手工快照保留；缩略图确实对应相同版本配置。

当前入口：[Core.cs](../code/src/Core.cs)、[Screenshots.cs](../code/src/Screenshots.cs)、[Controller.cs](../code/src/Controller.cs)。上游：[BackupManager.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/BackupManager.cs>)。Fences 来源：[快照模型](../references/Fences-4.0.0.3-analysis/features/06-snapshots.md)。

## LAYOUT-05 工作区档案与自动切换

**需求：** 工作、游戏、演示等场景可有独立分区集合和设置；可手动切换，后续可按前台应用自动切换。

**当前差距：** 现有 LayoutProfiles 保存显示器布局位置；CurrentWorkspace 是项目目录语义。二者均不等同于包含独立分区、规则和外观的完整 Profile。

**建议实现：** 使用明确的 ProfileId，分开保存全局设置、档案内容和显示器布局。手动切换先保存旧档案，再完整校验目标，失败回退。自动规则包含应用身份、目标档案、持续时间、优先级及退出后恢复策略；用户手动切换可暂停自动接管。前台检测需防抖，锁屏或无法读进程时保持原状态。

**验收：** 两档案切换不串配置；短暂切前台不闪烁；手动选择不被立即覆盖；应用退出时按策略恢复；改名不破坏规则引用。

上游实证：[ProfileManager.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/ProfileManager.cs>)、[AutomationManager.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/AutomationManager.cs>)。后者每秒检测前台并按延迟规则切换，栖桌可参考其状态模型而不照搬所有行为。

## LAYOUT-06 导入导出与迁移

**需求：** 导出分区或工作区，在另一台电脑预览导入，处理目录不同、重复 ID 和丢失资源。

**建议实现：** 包内清单声明格式版本、对象 ID、资源引用和路径映射。导入先解到受限临时目录，校验条目路径和资源大小，拒绝路径越界；生成 ID 映射并重写所有引用。展示合并/新增方案和无法解析项，确认应用时作为一个事务。跨电脑路径通过已知文件夹或用户显式映射迁移，绝不把所有路径强行转为相对路径。

Fences 导入应单独维护版本适配器；现有导入模型已支持分组、归属、页面，规则导入需要明确格式后再增加。组件包分享沿用现有能力，不再另造同名格式。

**验收：** 重复导入不覆盖无关对象；目标机器路径不同可修复；缺失项目可保留为待定位；取消后无配置变化。

当前入口：[Controller.cs](../code/src/Controller.cs)、[ComponentPackages.cs](../code/src/ComponentPackages.cs)。上游：[ImportTabManager.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/ImportTabManager.cs>)、[BackupManager.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/BackupManager.cs>)、[FilePathUtilities.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/FilePathUtilities.cs>)。
