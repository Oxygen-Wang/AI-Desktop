# 桌面接入与分区

## DESK-01 桌面承载

**需求：** 分区停留在桌面层，普通应用前台时不抢焦点；桌面空白、任务栏、原生图标的点击和右键仍正常。

**建议实现：** 复用当前 Shell 的桌面宿主定位与窗口绑定。校验宿主的窗口类、层级和进程，保存宿主句柄及进程标识；句柄变化后重新发现。透明区域的命中测试只保留分区操作所需范围。把窗口可见性、桌面绑定和临时置顶分别管理。

**验收：** Win+D 前后、切换普通窗口、打开桌面右键、拖动原生图标时均不被分区挡住；点击分区不把其他分区一起带到应用窗口上方。

当前入口：[Shell.cs](../code/src/Shell.cs)、[Controller.cs](../code/src/Controller.cs)、[ExplorerDesktop.cs](../code/src/ExplorerDesktop.cs)。参考：[Fences 桌面定位静态证据](code/Fences-3.1.6.1-decompiled/analysis-evidence/REA-STATIC-AUDIT-20261015.md)、[DesktopFramesPlus 非激活窗口](<code/DesktopFramesPlus-main/Code/Desktop Frames/NonActivatingWindow.cs>)。

## DESK-02 原生桌面图标协调

**需求：** 文件加入分区后，用户能清楚理解它的位置；避免同一项在原生桌面和分区重复出现。未加入分区的原生图标、回收站等应保留可用。

**当前差距：** 栖桌使用自己的文件视图；现有整层隐藏方案会同时隐藏所有原生图标，不能满足“只接管已分组项”。

**建议实现：** 先明确产品方案再改代码。逻辑归属模式保持文件路径，必须单独研究原生图标的逐项协调能力；不能把隐藏整个 SysListView32 当作逐项控制。另一方案是显式把文件移动到受管目录，并让分区映射该目录，此时属于真实文件操作，应提供操作预览、冲突处理和恢复记录。两种方案的数据语义不同，不能静默切换。

Fences 的原生装载与窗口挂接代码可用来理解问题复杂度；当前证据不足以给出稳定的逐图标接管算法。不要仅凭几个 ListView 消息就承诺完成兼容。

**验收：** 加入和移出分区后，桌面可见项与实际文件一致；删除分区不误删实体文件；回收站和未分组项仍可操作；异常退出能够恢复。

当前入口：[DesktopIcons.cs](../code/src/DesktopIcons.cs)、[ExplorerDesktop.cs](../code/src/ExplorerDesktop.cs)。参考同 DESK-01；上游 [DesktopIconManager.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/DesktopIconManager.cs>) 只作为独立对照，不据文件名推定已有逐项控制。

## DESK-03 桌面故障恢复

**需求：** Explorer 重启、桌面宿主消失、应用崩溃、休眠恢复后，Windows 桌面可继续操作，分区能够恢复。

**建议实现：** 保留现有周期校验，增加绑定状态记录：未发现、已绑定、失效、重试中。重试要退避，避免不断重建窗口。修改桌面可见性时记录原值与修改所有者；只有仍属于本次修改的状态才恢复。配置保存与桌面窗口销毁解耦，退出路径应幂等。

**验收：** 在测试环境真实重启 Explorer、结束栖桌进程、睡眠再唤醒；不得留下无法点击的桌面、永久隐藏图标、重复分区或多套恢复进程。

当前入口：[Controller.cs](../code/src/Controller.cs)、[DesktopIcons.cs](../code/src/DesktopIcons.cs)。本轮只定位代码，没有执行这些场景。

## GROUP-01 分区基础模型

**需求：** 创建普通分区或文件夹分区，改名、拖动、缩放、锁定；颜色和标题等属性持久化。

**建议实现：** 延用 Group 的稳定 ID。位置、页面、外观和数据源分别存储；分区类型显式区分普通集合、文件夹、组件。拖动过程中更新预览，结束后一次保存并形成一条撤销记录。锁定禁止几何修改，不应阻止正常打开文件。

**验收：** 重命名后归属不丢失；缩放有最小尺寸；重启后恢复；锁定、撤销、导入后 ID 不冲突。

当前入口：[Core.cs](../code/src/Core.cs)、[FenceWindow.cs](../code/src/FenceWindow.cs)、[DesktopCreation.cs](../code/src/DesktopCreation.cs)。参考：[Fences 分组模型](../references/Fences-4.0.0.3-analysis/features/02-groups.md)、[FrameDataManager.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/FrameDataManager.cs>)。

## GROUP-02 归属与手动排序

**需求：** 将文件加入、移出或转移到另一个分区；同一逻辑文件在普通分区中有明确归属；可手动排序。

**建议实现：** 用规范化身份作归属键，显示名仅用于展示。普通分区操作默认修改配置，实体复制移动使用 FILE-03。排序保存稳定的项目 ID 序列；名称等自动排序开启时，明确手动拖动是关闭自动排序还是临时覆盖。空白占位符可作为 P2 选项，不能伪装成文件路径。

**验收：** 大小写路径、快捷方式与目标文件的身份策略一致；跨分区拖放无重复、丢项；撤销恢复归属与顺序；移出后不会立即被自动规则重新收回，除非用户选择重新匹配。

当前入口：[Core.cs](../code/src/Core.cs)、[DragTransfer.cs](../code/src/DragTransfer.cs)、[DesktopItemDrag.cs](../code/src/DesktopItemDrag.cs)。参考：[IconDragDropManager.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/IconDragDropManager.cs>)、[手动排序与占位说明](code/DesktopFramesPlus-main/TIPS.md)。

## GROUP-03 分区内部标签页

**需求：** 一个分区内保存多个项目集合或目录，通过标签切换；不同于整个桌面的分页。

**当前基础：** Group 已有 Folders、FolderIndex 等多文件夹字段，需要先对照 UI，避免再建一套相同目录切换功能。

**建议实现：** 通用标签页使用 TabId、标题、数据源类型、项目集合、过滤和排序配置；活动标签只管理当前分区。关闭标签前明确项目是否只解除归属，避免连带文件删除。标签过多时提供溢出菜单。

**验收：** 切换不改变其他分区；重启恢复活动标签；移动标签后项目仍对应原 TabId；导出导入保持关系。

上游源码：[TabManager.cs](<code/DesktopFramesPlus-main/Code/Desktop Frames/TabManager.cs>) 的 AddNewTab、SwitchTabByFrame、MoveTab、DeleteTab。通用标签页列为 P2，先完成现有多目录能力的验收。
