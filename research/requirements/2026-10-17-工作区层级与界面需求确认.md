## 一、本次要解决的问题

1. 按 Alt+Space 或点击鼠标中键后，未选中的桌面分区偶尔也浮到其他窗口上方。
2. 控制面板左侧导航过于拥挤，“颜色和外观”等设置内容的布局也需要梳理。
3. 分区顶部栏拥挤，关闭分区的 × 太小、不容易点击。
4. 小猫点击唤起的工作区需要与桌面选中的工作区统一，避免两套内容和状态。
5. 分区缩成折叠栏后，图标太小、辨识不清，需要改善标题和操作入口。

本清单以最新截图、最新代码和本轮反馈为准。历史需求作为兼容约束，不表示本次重做所有功能。

## 二、已确认的行为

以下来自此前明确确认，除非用户在本文中修改，否则沿用。

| 项目 | 预期行为 |
| --- | --- |
| 工作区与分区 | 工作区就是现有桌面分区，不再另开工作区文件面板；保留内容、颜色、透明度、样式、位置和尺寸。 |

“取消选择”“从工作区移除”和“删除分区”是不同操作，按钮提示和执行结果应能区分。

## 三、分区层级修复范围

### 目标

- 只有本次唤起的已选分区进入前景。
- 未选中的分区和桌面组件保持桌面层级。
- 取消单个选择、取消全部选择后，相关分区回到桌面层。
- 收起、再次唤起、切换页面、应用设置或重建窗口后，显示状态与层级保持一致。
- 仅选择工作区不应自动使它置顶；由唤起操作决定是否进入前景。

### 已发现的代码问题

当前取消单个选择的路径没有同步解除窗口置顶，可能留下“已经取消选中但仍浮在前面”的窗口。
这是一处已发现的问题；其他偶发浮起现象仍需结合窗口恢复、桌面挂接及重建流程验证，不能据此认定全部根因已查明。

### 保留的操作

- 桌面空白处中键左右拖动仍用于翻页。
- 文件拖入拖出、面板内文件夹导航、标题改名等现有操作继续保留。
- 不改变真实文件的存放方式和桌面恢复职责。

## 四、界面调整方案（建议，待确认范围）

### 4.1 分区顶部栏

- 标签、顶部空白拖动区域、右侧操作区分开排布。
- 标签之间增加适量间距，保持字体大小一致。
- × 固定在操作区最右端；建议图标约 18 DIP，点击区域至少 32×32 DIP。
- 选择、忽略等按钮使用统一的尺寸、间距和悬停反馈。
- 顶栏建议高度约 40–44 DIP，以实际显示效果调整。
- 操作按钮出现时不覆盖标签，也不导致标签突然跳动。
- 窄面板优先让标签横向滚动，不通过缩小按钮解决拥挤。
- 标签名称较长时省略显示，悬停可查看完整名称。
- 双击标签改名、双击顶部空白折叠等现有操作，不能被新按钮区域干扰。

### 4.2 控制面板左侧导航

- 将相互紧贴、凸起的大圆角按钮改为简洁导航列表。
- 当前页面保持明确高亮，其他项目采用较轻的背景。
- 统一文字对齐、行高和间距，保留合理滚动能力。
- 通过减少装饰和整理间距改善拥挤，不缩小字体来塞入更多项目。

### 4.3 控制面板右侧设置内容

- 统一标签对齐、输入框宽度、按钮高度及分组间距。
- “颜色和外观”按背景、文字、图标、组件等内容组织。
- 宽窗口可采用双列，窄窗口改为单列，避免遮挡和横向溢出。
- 常用设置直接可见，细调项目继续按需展开，兼顾紧凑和可读性。
- 调整共用布局函数，让其他设置页获得一致的排版。

以上尺寸均为建议的逻辑尺寸，需适应 Windows 缩放比例，不是固定截图像素。

### Q1：点击已选分区标题的鼠标中键，操作哪些分区？

- [x] A．切换所有已选分区，与 Alt+Space 完全一致。
- [ ] B．只切换当前点击的分区，Alt+Space 才操作全部已选分区。

### Q2：中键点击未选中的分区标题，如何处理？

- [x] A．不改变工作区选择和层级，需先通过选择按钮或 Ctrl＋左键选中。
- [ ] B．将该分区加入已选集合，再按 Q1 的规则切换。

这里仅指点击标题；桌面空白处中键拖动翻页不受影响。

### Q3：已明确，顶部 × 关闭面板

用户最新说明取代原删除方案：顶部 × 收起当前分区面板，不删除配置或文件。几个面板组合后作为一个分区，最右侧 × 收起整个组合分区。

### Q4：本次 UI 调整范围？

- [x] A．分区顶部栏＋控制面板左侧导航＋右侧设置内容，一起调整。
- [ ] B．只调整分区顶部栏和左侧导航，暂不调整右侧内容。
- [ ] C．先只调整分区顶部栏，控制面板之后再改。

### Q5：已明确，不再打开额外面板

按用户最新要求，小猫、Alt+Space 和托盘统一操作桌面分区。无选择时建议提示先选择分区，不能回退到旧工作区面板。

### Q6：小猫悬停时是否自动打开工作区？

- [x] A．悬停只显示提示或动画，点击才切换工作区。
- [ ] B．悬停一段时间后仅显示已选工作区，不执行收起；点击仍切换显示／收起。

如果选择 B，悬停打开后紧接的同一次点击不应马上把工作区关闭；拖动、右键菜单和文件拖放期间不触发悬停打开。

### 8.2 新增需求：统一小猫与桌面工作区

用户已明确提出“统一”，建议按以下行为落实；细节随本清单一并确认。

- 小猫点击、Alt+Space 和托盘工作区入口操作同一批已选桌面分区。
- 保持原分区的位置、大小、标签、忽略规则和当前浏览目录。
- 一次操作就显示／收起目标分区，不能先关闭另一套面板后再要求点击一次。
- 显示状态混合时，建议第一次操作将全部已选分区显示到前景；全部已在前景时才统一收起。
- 未选择工作区时，所有入口都按 Q5 执行。
- 小猫提示、动画和右键菜单反映相同状态。
- 中键作用范围仍由 Q1、Q2 决定。
- 历史工作区文件夹标签不能直接丢弃。迁移为普通桌面文件夹分区后加入同一个工作区集合；迁移保留恢复信息，不移动真实文件。不再保留旧面板作为唤起入口。
- 拖文件夹到小猫的行为建议与“添加普通文件夹分区”共用流程，完成后加入同一个工作区集合，不再自动创建另一套文件面板。此项属于待确认方案。

### 8.3 新增需求：折叠栏清晰可辨

本节暂按“分区折叠后仅留下顶部栏”理解；如果指的是其他缩小形态，可在确认时补充截图说明。

- 折叠只隐藏内容，不缩小顶部字体和按钮。
- 建议折叠栏高度为 44–48 DIP，标题至少 16–18 DIP，功能图标约 18–20 DIP，点击区域至少 32×32 DIP；以实际预览调整。
- 保留当前标签名称和清晰的展开入口；不能折叠成没有名称的空白条。
- 操作图标增加对比度，避免小字形叠在透明背景上看不清。
- 普通操作按钮继续遵守悬停显示规则，标题和展开入口保持可发现。
- 空间不足时滚动或省略标签名称，悬停显示完整名称，不压缩操作按钮。
- 单标签、多标签、贴底部折叠和悬停临时展开采用同一套尺寸约定。

## 九、忽略规则设计（用户已同意由助手确定细节）

- 全局规则提供默认行为；每个分区可以追加自己的规则，也可以移除继承的全局规则。
- 在分区里删除一条全局规则，仅对当前分区停用它，其他分区继续生效；提供“恢复继承”。全局规则页删除才影响所有分区。该区分已由用户确认。
- 几个面板合并后作为一个分区，共用规则编辑入口；不再让各标签各自维护互相矛盾的规则。
- 编辑器同时展示“继承的全局规则”和“当前分区规则”，明确标注作用范围；允许逐条启停、编辑、删除及多行文本编辑。
- 顺序为全局基础规则、分区规则，同层最后匹配的规则决定结果；分区的 `!` 例外可恢复显示。被忽略的父目录需先恢复，避免深层扫描造成性能问题。
- 语法参考 [Git 官方 gitignore 文档](https://git-scm.com/docs/gitignore)：支持注释、空行、通配符、目录规则、根路径和 `!` 例外。路径采用 Windows 文件系统比较语义。这里是显示规则，不依赖文件是否被 Git 跟踪。
- 导入 `.gitignore` 或文本规则时复制到当前分区；导入后可逐条修改，原文件和其他分区不受影响，不自动被源文件更新覆盖。
- 多文件夹分区的手写通用规则默认作用于所有根目录；导入规则保留对应目录基准，导入到其他分区时可选择基准。底层保留来源信息，但用户始终在一个分区规则页管理。
- 拖到忽略按钮默认只忽略这个具体项目，目录包含其内容，不自动忽略所有同名文件；规则仍属于组合分区，路径绑定到实际来源，避免误伤其他文件夹。
- 原分区合并时保留来源路径范围、已有规则及本地停用项；合并后的编辑统一进行。拆开时复制适用规则，避免共享可变列表。
- 全局规则本地停用使用稳定标识；全局规则修改文本后，该分区的停用状态仍保留。
- 忽略只影响分区内容与分区搜索展示，不删除或移动真实文件，不取消桌面恢复记录；允许临时查看被忽略项目和匹配原因，方便恢复。
- 不默认导入大范围隐藏规则；需要用户主动启用或导入。旧配置迁移保留原有显示结果。

验收：两个分区继承同一全局规则，其中一个取消继承，只有它恢复显示；导入后编辑不改源文件；组合分区切换标签共享规则；精确拖入忽略不影响同名其他文件；`!` 例外、目录恢复及重启持久化正确。
