# 全局快捷搜索「搜索全部」需求与实现方案

日期：2026-10-17 · 状态：**需求稿，未实现** · 参考源码：[references/EverythingQuickSearch](../references/EverythingQuickSearch)（MIT）、[references/DeskFrame](../references/DeskFrame)（MIT）

---

## 一、为什么要做

现在栖桌的搜索有两个入口，但都不是"随时随地搜全部"：

| 入口 | 现状 | 问题 |
| --- | --- | --- |
| `Alt＋Space` 工作区搜索 | `WorkspaceSearchWindow`，范围默认当前项目 | 想搜别的东西得先切项目，或手动点"全盘" |
| 文件搜索设置页 | 只能看状态、启停 Everything | 没有唤起入口 |

用户场景：**任何程序前台时按一个键 → 输入名字 → 直接打开/定位文件**，不关心这个文件属于哪个项目。

参考对象 `EverythingQuickSearch`（EQS）就是干这个的：常驻、全局键盘钩子、监听 Win 键、失焦自动隐藏、Everything 出结果。

---

## 二、需求（可验收）

1. **全局唤起**：在任意程序前台时按快捷键（默认 `Ctrl＋Alt＋Space`），弹出搜索条并聚焦输入框；再按一次收起。
2. **默认搜全部**：唤起后范围是「全部」，即 Everything 索引全盘；没有 Everything 时退化为"桌面 + 已连接项目"。
3. **不打断**：Esc 收起；点击别处失焦收起；不抢当前窗口的键盘输入超过必要。
4. **结果可用**：↑↓ 选择，Enter 打开，`Ctrl＋Enter` 在资源管理器定位，结果显示名称/所在文件夹/修改时间。
5. **可关**：设置里能关掉这个快捷键，且不与已有 `Alt＋Space`（项目搜索）冲突。
6. **可诊断**：Everything 没连上时，搜索条明确显示"本机搜索 · 连接 Everything 可搜全盘"，不静默失败。

不做的：不接管 Win 键开始菜单搜索（EQS 的做法，靠全局键盘钩子，和 PowerToys、输入法、杀软冲突面太大）；不做内容检索（只搜文件名/路径元数据）。

## 三、参考实现要点（EQS 怎么做的）

| 做法 | 位置 | 说明 |
| --- | --- | --- |
| **Everything64.dll 直连** | `Everything/Everything.cs` | P/Invoke `Everything_SetSearchW` / `SetSort` / `SetOffset` / `SetMax` / `SetRegex` / `Everything_QueryW`，比 CLI 少一次进程启动和临时 CSV 文件 |
| **异步回调不阻塞 UI** | `Everything/EverythingService.cs` | `SetReplyWindow(hwnd)` + `SetReplyID`，在 `WndProc` 里用 `Everything_IsQueryReply` 认领回包，再 `GetResultFullPathName` / `GetResultDateModified` / `GetResultSize` |
| **请求字段白名单** | 同上 `Everything_SetRequestFlags` | 只要 `FILE_NAME / PATH / DATE_MODIFIED / SIZE`，不多取 |
| **失焦即藏** | `MainWindow.xaml.cs` `OnDeactivated` | 点别处就 `Hide()`，不占焦点 |
| **键盘切换分类** | `Alt＋1..8` | 文档/图片/文件夹等类别切换，`Alt＋R` 切正则 |
| **全局键盘钩子** | `MainWindow.xaml.cs` `M_GlobalHook_KeyDown` | 监听 Win 键并接管开始菜单搜索——**本项目不采用** |

EQS 依赖：`Everything64.dll`（随 Everything 安装）、WPF UI、MouseKeyHook、SVG.NET。栖桌只借鉴前两项的**接口用法**，不引入任何第三方包。

## 五、实现步骤

### P0 热键 + 全盘范围（最小可用，不碰搜索内核）

1. `ManagerWindow` 注册/注销 id 8 热键，失败时 `SetStatus("Ctrl＋Alt＋Space 已被占用…")`，与现有 `Alt＋Space` 冲突提示一致。
2. `WM_HOTKEY` 分支调用 `ShowWorkspaceSearch(true,true)`。
3. `WorkspaceSearchWindow` 在 `allFiles` 时把范围切到全部，摘要显示 `Everything · N 项` 或 `本机搜索 · …`。
4. 设置页加开关，存 `State.QuickSearchAll`。

验收：任意程序前台按 `Ctrl＋Alt＋Space` 弹出并聚焦；`Alt＋Space` 行为不变；关闭开关后热键不再注册。

### P1 Everything DLL 直连（可选，性能与稳定性）

1. 新增 `code/src/EverythingSdk.cs`：`DllImport("Everything64.dll")`，`HwndSource` 回包 + `TaskCompletionSource`，接口 `Task<SearchResult[]> QueryAsync(string expr,int max,int offset,bool regex)`。
2. `FileSearch.Query` 里优先 DLL（`File.Exists` 探测 dll），失败或未安装时回退现有 `es.exe`。
3. 好处：无 5 秒超时、无临时 CSV、可取消；坏处：多一个原生依赖，必须"探测不到就走回退"。

验收：装 Everything 时走 DLL，卸载后自动回退 CLI，两条路径结果一致。

### P2 分类过滤（锦上添花）

文档/图片/文件夹/今天四个筛选按钮已经存在（`WorkspaceSearch.cs:90` 的 `AddFilter`），再配 `Alt＋1..4` 直接切换。

## 六、风险

| 风险 | 处理 |
| --- | --- |
| 快捷键被别的软件占用 | `RegisterHotKey` 返回 false 时明确提示，不静默；设置里显示当前占用状态 |
| `Everything64.dll` 版本/位数不匹配 | 只探测 `Everything64.dll`（x64 程序），探测失败即回退 es.exe |
| DLL 属于第三方运行时，AGENTS.md 禁止引入新运行时 | DLL 是**可选加速路径**，不打包进 `dist`，缺失时功能仍完整 |
| 全局热键在提权窗口前台时无效 | Windows 限制，文档里写明，不做绕过 |
| 弹窗抢焦点打断输入 | 复用现有窗口的"失焦即藏"和 `ShowActivated` 策略，参照 `WorkspaceSearchWindow` 现有实现 |
