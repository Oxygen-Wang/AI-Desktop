# 分区标签栏统一（Chrome 式）

日期：2026-10-17
状态：已实现并通过编译、自测与原生测试。

## 一、需求

用户要求：

> 文档、图片、桌面等所有分区都类似 Chrome 的标签页设计，支持动态拖动进出。所有分区平权设计，只是规则不同，将分区抽象为函数。

确认后的范围（用户选择）：

1. 每个分区窗口顶部一条标签栏，分区在桌面上的位置和尺寸不变。
2. 自身、文件夹映射、合并进来的分区都是同一种标签，可拖出成独立分区、拖到别的分区窗口合并。
3. 只统一桌面分区的标签实现，不改造 `WorkspacePanel` 的 `PanelTabs`。

## 二、模型：分区就是一种标签

新增 [PartitionTabs.cs](../code/src/PartitionTabs.cs)：

- `PartitionTab`：`Host`（窗口分区）、`Owner`（对应分区）、`Folder`（文件夹来源）、`Title`、`Active`、`Pinned`。
- `PartitionTabs.Of(state, host)`：一个函数生成窗口的全部标签，顺序为自身 → 文件夹映射 → 合并分区。
- `PartitionTabs.FolderOwner(state, host)`：活动成员自带目录时优先显示成员的文件夹标签，否则显示窗口自身的；合并两个文件夹分区后仍能切换。
- `PartitionTabs.Items(store, owner, folder, search)`：唯一内容入口。文件夹标签读磁盘目录，普通分区读 `Items`；两者都走 `Store.ItemsAt`，共用忽略规则、搜索和排序。

数据仍只有两个来源，没有新增字段：

- 文件夹标签：`Group.Folders`（旧配置只有 `Folder` 时退化为一个标签）。
- 合并分区标签：`Group.HostGroupId`。

文件夹标签拖出后由 [Controller.Tabs.cs](../code/src/Controller.Tabs.cs) 变成真正的 `Kind=文件夹` 分区，因此“标签”和“独立分区”之间可以双向转换。

## 三、交互

| 操作 | 结果 |
| --- | --- |
| 左键点标签 | 切换；文件夹标签可继续双击子文件夹，再点当前标签回到根目录 |
| 双击分区标签 | 内联改名（文件夹标签不改磁盘目录名，因此不提供） |
| 悬停标签 | 显示 ×；成员标签可右键固定，固定后隐藏 × |
| × | 关闭标签：成员标签恢复独立分区，文件夹标签只移除映射 |
| 拖动标签到另一个分区标题栏 | 合并/移动；文件夹的目录与忽略规则一起移动 |
| 拖动标签到桌面空白处 | 拆成独立分区；文件夹标签变成独立文件夹分区，外观、目录与目录级忽略规则一起带走 |
| 拖动分区自身标签 | 移动整个分区；拖到另一个分区标题栏则整组合并 |
| ＋ | 添加文件夹标签，或新建一个空分区标签 |
| 右键标签 | 切换、重命名、固定、在资源管理器打开、拆成独立分区、关闭 |

标签栏始终显示；折叠成一条时退回单行标题，拖动折叠栏仍保留。`颜色和外观` 页移除了原来的“显示标题”单选项，改为说明标签本身就是标题。

旧 `Kind=工作` 分区在 `Store.Validate` 中无条件迁移为普通分区 + `图片` 子分区（幂等），因此老配置里的“文档/图片”也进入同一条标签栏。`WorkView` 只保留为旧配置字段，不再参与界面。

## 六、已知限制

- 标签暂不支持在同一栏内手动排序；顺序为“自身 → 窗口文件夹 → 活动成员文件夹 → 合并分区”。
- 单文件夹分区的文件夹标签拖出后，原分区会保留为一个空分区，不会自动删除其配置。
- 文件夹标签的忽略规则随目录移动，但绑定在该分区上的独立 `.gitignore` 导入副本仍留在原分区。
- 自身标签拖动到另一个分区会整组合并（沿用原窗口标题栏行为）；取消已选工作区后才合并的规则不变。
- 高 DPI 下拖出分区的位置仍沿用旧的物理坐标换算，未在本次单独校准。
