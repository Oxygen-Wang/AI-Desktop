# 栖桌 · AI Desktop

第一次打开项目，先看[项目思维导图与目录导航](PROJECT_MAP.md)。主程序使用 C# / WPF；`code` 只放构建 App 所需的文件，`dist` 是本机构建，`output` 是对外分享包。

一个正在开发的 Windows 桌面整理软件。当前交付核心预览版 0.7.1：可以运行，不代表已经完成 Fences 3 功能等价。

本轮修复与范围见 [桌面核心与文件搜索](research/CORE-0.6.md)。Ditto / 剪贴板扩展暂缓，不参与当前构建。

## 启动

在 PowerShell 中执行启动脚本，它会选择 `dist\latest.txt` 指定的最新构建：

```powershell
& D:\fences\code\start.ps1
```

需要直接启动桌面模式时，可以给最新 EXE 传入 `--desktop`：

```powershell
$taskExe = (Get-Content D:\fences\dist\latest.txt).Trim()
& $taskExe --desktop
```

先显示管理面板。点击“窗口预览”查看分组；点击“启动桌面模式”将本软件的分组窗口挂接到桌面承载窗口。可以拖动分组标题栏、拖动右下角改变尺寸、点击右上角 ⌃ 折叠，双击标题或边框打开对应的系统文件夹，或把文件拖入分组。双击项目可打开，右键可查看文件位置、复制路径或改变分组。

关闭面板会收至系统托盘；通过“退出栖桌”彻底退出。Ctrl+Alt+D 显示/隐藏本软件分组，Ctrl+Alt+左右方向键切换页面。若热键冲突，面板会显示提示。

在桌面空白处按住鼠标中键左右拖动可以翻阅桌面页面：当前页的分区与组件跟手一起移动，松手后按拖动方向翻页，滑行接着松手时的指针速度（约 0.28–0.62 秒：慢速松手用平缓滑动，快速轻扫以同一速度起步后减速）；拖动不足 90 像素则缓动回到原位。翻页时新旧两页同时滑动，期间继续滑动或再次翻页不会被忽略。

### 桌面没有显示时

通过旧版面板的“退出栖桌”退出旧进程，再运行 `code/start.ps1` 启动最新版本，点击“启动桌面模式”。关闭面板右上角的叉号只会收至托盘，不会退出旧版。

本次修复严格识别 Explorer 的 Progman / WorkerW 桌面窗口，避免误选文件夹映射视图；透明分组保持顶层窗口的屏幕坐标，通过桌面窗口所有权连接桌面。屏幕外分组会在启动显示时自动恢复到可触及的位置，正常的副屏负坐标会保留。也修复了导入对话框的初始路径问题。

为确认实际效果，建议暂时停用 Fences 的桌面整理功能，关闭 Fences 设置窗口并不一定会停用它。无需卸载 Fences；本机窗口挂接检查在 Fences 仍运行时已经通过。具体视觉重叠和前后台行为还需要实测。

## 当前功能

- 桌面分组、窗口预览、标题拖动、尺寸调整、折叠、位置锁定、颜色和透明度。分区可重叠；选中期间移动的分区在取消选中时恢复原位置，合并分区的标签可用左键拖出。
- 文件/快捷方式拖入分组，改变归属，打开和定位文件。
- 文件夹映射：直接枚举文件夹内容，定时刷新，按名称、类型或修改时间排序。
- 名称搜索、分页、全局隐藏、隐藏排除项。
- 扩展名和名称包含规则，按顺序首次匹配，自动归类新桌面文件。
- JSON 配置持久化、布局快照、恢复、撤销。
- 从 `research\evidence\fences-config.json` 导入 Fences 分组、图标归属和页面；规则暂不导入。导入后自动归类关闭，可撤销导入。
- 基于规则的分类建议；Ollama / 兼容 Chat Completions 服务的 AI 请求、建议预览和勾选应用。

分组操作只改变本软件配置中的归属，文件仍在原路径。文件夹映射窗口显示真实目录内容，当前拖入该窗口不会触发文件移动。移除分组或项目不会删除磁盘文件。

## 配置与验证

本机配置保存在 `%LOCALAPPDATA%\QiDesk\state.json`，快照在同目录 `snapshots`。写入使用临时文件替换并保留备份，格式错误的原配置会保留副本。

```powershell
& D:\fences\code\build.ps1
$taskExe = (Get-Content D:\fences\dist\latest.txt).Trim()
$taskTests = (Get-Content D:\fences\dist\latest-tests.txt).Trim()
& $taskTests --self-test --native-test
& $taskExe --render-settings
```

构建现在产出四个产物：`QiDesk-*.exe`（正式程序）、`Mcp-QiDesk-*.exe`（MCP 服务）、`Ai-QiDesk-*.exe`（AI 功能独立进程）和 `Tests-QiDesk-*.exe`（测试，含 `--self-test`）。自检入口只存在于测试产物中，正式程序与 MCP、AI 产物不再包含测试代码。

构建使用系统 .NET Framework 4.x 编译器，无需下载 SDK。每次构建生成带时间标识的独立 EXE，避免覆盖被占用的文件。518 项自检（另有原生窗口检查）覆盖规则、唯一归属、撤销、快照、重新加载、移出分组的排除状态、文件夹枚举和配置导入，以及误选桌面窗口的防护、屏幕外恢复、真实透明分组的挂接、坐标保持和隐藏后显示；其中包含对代码守卫基线自身的校验，以及 AI 分类逻辑与 AI 独立进程的端到端协议检查。原生测试会短暂显示本软件的测试分组，随后关闭。`--render-settings` 只渲染本软件界面，生成十三个 `dist\settings-*.png` 及分组/映射预览。示例映射仅写入独立 render-state，不写入实际配置。

构建结束后会自动运行代码守卫 `code/check-code.ps1`，只报警不阻断构建。规矩和它背后的失败案例见 [CODE-RULES.md](CODE-RULES.md)；提交前守卫会拦下新增违规，每个克隆启用一次即可：

```powershell
git config core.hooksPath .githooks
```

## 组件渲染类型扩展

插件清单仍为 JSON 描述，不执行外部代码；本轮把可用渲染类型从八种扩展到十二种，内置组件、自定义 `.qidesk-plugin.json` 插件与组合包都可选用：

- 计算器（calc）：桌面四则运算，支持括号与小数，实时预览结果；不执行脚本，表达式由本地解析器求值。
- 习惯打卡（habit）：每天点一次记录打卡，显示连续天数与累计天数；打卡记录保存在本机组件数据中，不随组合分享导出。
- 系统状态（system）：读取 CPU 占用、内存占用与所选磁盘可用空间及开机时长；在设置中可指定盘符，留空使用系统盘。
- 照片轮播（photos）：循环播放指定文件夹内的图片，支持左右切换，每 8 秒自动换一张；在设置中点“选择文件夹”指定目录。

自定义插件、组合导出与安装预览沿用原有流程；新类型同样参与组件库预览、尺寸下限校验和页面自动排列。示例见 code/plugins/examples/daily-water.qidesk-plugin.json 与 utility-desk.qidesk-pack.json。预览见 dist/component-qidesk.calc-preview.png 等。

## 日历与时钟（农历）

日历组件对齐当代中文日历：每格显示公历日与农历小字，初一显示月份，节气由本地公式计算，公历节日与春节、元宵、端午、七夕、中秋、重阳、腊八、除夕优先显示；周末用强调色，今天整格高亮。可在设置中开启“在日历中显示时钟”，在标题下显示当前时间与“农历九月初七”；时钟组件也在日期行追加农历日。设置含“显示农历、节气与节日”“在日历中显示时钟”“一周从周一开始”，默认周一开始。农历数据覆盖 1900–2100，超出范围回退公历；日历缩小时内容可滚动。实现与验证见 research/COMPONENT-LIBRARY.md，预览为 dist/component-calendar-preview.png 与 dist/component-clock-preview.png。

## 网易云音乐组件

新增 `music` 渲染类型（内置组件“网易云音乐”，id 为 qidesk.music，强调色 #C20C0C）。它读取网易云音乐客户端主窗口标题（播放时形如“歌名 - 歌手”）作为正在播放信息：显示歌名、歌手；按钮“上一首 / 播放 / 暂停 / 下一首”通过系统媒体键控制当前播放器；未检测到客户端或未播放时显示相应提示。网易云没有公开的本地播放接口，因此不显示专辑封面与进度，也不读取账号信息。若客户端装在别处或想指向其它播放器，可设置环境变量 `QIDESK_MUSIC_PROCESS` 指向对应进程名。实现与验证见 research/COMPONENT-LIBRARY.md，预览为 dist/component-qidesk.music-preview.png。

## 桌面分区自动排列（0.7.1）

主页和托盘新增“自动排列分区”。“布局和快照”可一键排列当前页或全部页面，也可开启“新增分区、尺寸和显示器变化时自动排列”。该开关默认关闭。

## 桌面分区标签栏与多文件夹

每个分区顶栏只有一条类似 Chrome 的标签栏：分区自身、文件夹映射和合并进来的分区都是同一种标签，区别只在内容来源——文件夹读磁盘目录，普通分区读自己的成员。点标签切换，悬停后点 × 关闭；把标签拖到另一个分区的标签栏即可合并/移动，拖到桌面空白处则变回独立分区。文件夹标签也能直接拖出成独立文件夹分区，外观、目录和该目录的忽略规则一起带走，磁盘文件不动。双击分区标签改名，标签过多时横向滚动。＋ 可添加文件夹标签或新建一个空分区标签。

把文件夹拖到面板顶部栏位（或用 ＋ 选择）也能新增文件夹标签，双击文件夹进入子文件夹，文件区第一格是“↑ 上一层”，再次点击当前标签回到根目录。每个标签各自记录浏览位置。

“生成默认面板”（主页按钮；首次运行自动创建一次）在右下角竖排最多三个面板，宽度约 6 个图标，高度按工作区高度三等分：文件夹（桌面 + 多文件夹标签）、文档（含图片标签）、应用（桌面上的程序与快捷方式）。

排列默认只移动位置、不拉伸分区；可选“排列时按内容缩小分区（只缩不放）”按文件数量收缩多余空白，空分区收到最小尺寸。实现与验证见 research/DESKTOP-PANELS.md。

## 桌面工作区与小猫

工作区直接使用桌面上的分区。Ctrl＋左键点击标题或点右上角圆点选择多个分区后，点击小猫或按 Alt＋Space 把已选分区提到当前软件前方；再次操作将它们放回桌面层，分区仍可见。Ctrl＋左键在桌面空白处拖出选框时，会选中框内分区；选中多个后拖动任一选中分区的标题栏或 ⠿ 手柄，会按相同位移一起移动。前台分区不是始终置顶，点击其他应用后会按 Windows 普通窗口层级切换。中键点击已选分区可收起或再次唤起。分区之间允许重叠；桌面模式会尝试将原生图标移出分区范围。所有分区共用顶栏的标签规则：自身、文件夹映射和合并分区平权，拖动标签即可拆出或合并，右键可固定标签，固定标签隐藏关闭按钮；颜色、透明度、位置、尺寸和当前目录保持原样。未选中的分区与组件留在桌面层，无选择时提示先选择分区，不另开工作区面板。`Ctrl＋Alt＋Backspace` 取消全部选择并回到桌面。忽略规则输入可用中文或英文逗号、分号及空格分隔，一次添加多条并逐条显示。

顶部最右侧 **× 收起整个分区**，组合分区包含的标签一起收起，不删除配置或磁盘文件。控制面板分区卡片右键“在桌面显示分区”可以恢复；真正删除分区使用右键菜单或控制面板的删除入口。标签上的 × 只关闭该标签；拖到桌面空白处才是拆出独立分区，文件夹标签则变成独立文件夹分区。

当前分区获得焦点后，`Ctrl＋F` 打开名称搜索，再按一次关闭；搜索框旁的“关闭搜索”只关闭搜索。文件夹分区在当前目录与子目录中查找，普通分区匹配已有成员，最多显示 2000 项。搜索在后台执行，切换查询、关闭搜索或关闭窗口会取消旧任务；遵循与正常列表相同的忽略规则，不搜索文件内容。小猫右键和托盘仍提供全盘搜索入口。

忽略规则按全局基础规则、分区规则处理，支持 Git 风格的目录、通配符和 `!` 例外；忽略整个父目录时需先恢复父目录，才会搜索其子目录。在分区规则页可以“仅此分区删除”继承的全局规则，或者复制为独立规则后修改，其他分区不受影响；“恢复继承”重新采用全局规则。导入 `.gitignore` 或 `.cursorignore` 后修改栖桌中的副本，不写源文件。几个分区合并后共用规则，拆出时复制适用的规则与继承例外。把文件拖到顶部忽略图标默认只忽略该具体路径，不误伤其他文件夹中的同名文件。

顶部按钮在悬停或拖入时显示，点击区域统一加大。折叠栏保留清晰的名称、48 DIP 栏高和 ⠿ 拖动手柄；拖动保留折叠状态、原展开高度与布局保存，悬停展开延迟触发，避免抢走起拖操作。控制面板导航使用无凸起阴影的列表，“颜色和外观”宽窗口双列、窄窗口单列。

小猫保留**默认猫／毛绒三花／矢量猫**形象，三花素材由用户后续处理；75%–200% 大小会同时缩放形象。悬停只改变提示和动画，点击才切换工作区。拖文件夹到小猫会添加或复用普通桌面文件夹分区并选中。历史工作区文件夹标签首次使用时迁移到桌面分区，保留目录与忽略副本，迁移前保存撤销快照。ChatGPT／OpenCode 连接已记入需求，本轮尚未实现。

验证资料见 `research/requirements/2026-10-17-工作区层级与界面需求确认.md`，界面预览生成在 `dist/unified-*-preview.png`。跨显示器 DPI 切换与真实 Explorer 重启仍需实际环境验证。

## AI 布局档案与命令行应用

`%LOCALAPPDATA%\QiDesk\desktop-layouts.json` 是一个可直接阅读和编辑的 JSON：顶层包含多份存档（`archives`）和当前 `active`，每份存档保存分区、分类规则、页面、桌面位置和可选的 `layout.template`。AI 修改这个文件后，可以先预览，再从命令行应用；应用只改变栖桌的归属和布局，不移动、不删除磁盘文件，应用前保存快照，可撤销。完整格式、规则语义和布局风格建议见[需求与示例](research/requirements/2026-10-17-AI布局档案JSON与多存档需求.md)。

常用命令（在 `dist` 目录或使用完整路径）：

```powershell
$qidesk=(Get-Content .\latest.txt).Trim()
& $qidesk --layout-list
& $qidesk --layout-preview work
& $qidesk --layout-apply work --include-excluded
& $qidesk --layout-apply work --layout-only
& $qidesk --layout-export work --name 工作桌面
& $qidesk --layout-undo
```

`--layout-apply` 默认同时按规则整理桌面；`--layout-only` 只移动/新增分区，不改归属；`--include-excluded` 允许重新整理此前手动移出的项目。规则按数组顺序首次匹配，未匹配项目默认留在桌面；`fallback.unmatched` 可改为 `partition` 并指定收件箱。命令行与 MCP 共用 `LayoutArchives`，实现位于 [LayoutArchives.cs](code/src/LayoutArchives.cs)、[LayoutCli.cs](code/src/LayoutCli.cs)、[LayoutBridge.cs](code/src/LayoutBridge.cs)、[LayoutCommands.cs](code/src/LayoutCommands.cs)。

## AI 独立进程（sidecar）

AI 分类功能住在独立构建产物 `Ai-QiDesk-*.exe` 里，主程序以子进程方式调用它，两边只有一条进程边界，不让 AI 细节渗进主程序：

- 主程序（[AiClient.cs](code/src/AiClient.cs)）只负责：按 `dist\latest-ai.txt`（或程序目录下最新的 `Ai-QiDesk-*.exe`）发现组件、隐藏窗口拉起、等就绪帧、按请求 id 收发 NDJSON、超时或异常退出时杀进程重拉、退出栖桌时 `shutdown` 并 Kill 兜底。它不知道提示词、HTTP 和解析规则。
- AI 进程（[AiSidecar.cs](code/src/AiSidecar.cs) 服务循环 + [AiCore.cs](code/src/AiCore.cs) 分类逻辑）只认纯数据：文件名、扩展名、是否文件夹、分组 id 和名称进，分类建议出；不引用 `Store`、`Controller` 和任何窗口。AI 进程崩溃不会带走主程序，替换实现也不必改主程序。
- 协议是一行一帧的 NDJSON（`request` / `response` / `event` 信封，带协议版本和请求 id），命令现有 `ping`、`recommend`、`shutdown`，后续 Skill 命令都往这个进程里加。完整约定、错误码和生命周期见 [research/AI-SIDECAR.md](research/AI-SIDECAR.md)；设计参考了 Tauri 本地 AI sidecar 契约与 Matemium 的 sidecar IPC 协议（克隆在 `references/matemium-sidecar`，仅阅读参考）。

行为与迁移前一致：最多 300 个桌面项、忽略规则在发送前过滤、Ollama 与 Chat Completions 两种地址形态、90 秒超时、建议可逐项勾选应用和撤销。隐私不变式不变：只发送文件名、扩展名、是否文件夹与分组名。

## 自定义桌面项显示图标

桌面分区里右键任意项目（文件、文件夹、快捷方式都可以），选择“更换显示图标…”。来源可以是 `.ico`、`.exe`、`.dll`、`.icl`，也可以是 `.png`、`.jpg` 等图片；程序与库文件会列出内含图标供挑选序号，图片按原图显示。已自定义的项目菜单里会显示“更换显示图标…（已自定义）”和“恢复默认显示图标”。

只改变栖桌内的显示：不写真实文件、不改 `desktop.ini`、不通知资源管理器，随时可以恢复，也可以撤销（设置前会记撤销点）。图标来源文件被删除或读不出来时自动回退系统图标，并在状态栏说明。重命名或移动项目（含移动父目录）后图标跟着走。设置页“颜色和外观”会显示已自定义的数量，并可“全部恢复默认图标”。

配置存在 `state.json` 的 `CustomIcons`（项目路径 → 图标来源与序号），上限 2000 条，只接受绝对路径；实现见 [code/src/CustomIcons.cs](code/src/CustomIcons.cs)，渲染入口在 `FileIconPresentation.Themed`（[code/src/AppIconSkins.cs](code/src/AppIconSkins.cs)），测试见 [code/src/tests/CustomIconTests.cs](code/src/tests/CustomIconTests.cs)。

## 更换快捷方式图标

桌面分区里右键任意快捷方式（`.lnk`），菜单新增“更换快捷方式图标…”和“恢复快捷方式默认图标”。选一个 `.ico`、`.exe`、`.dll` 或 `.icl` 文件即可换成它的图标（取来源文件的第 0 个图标）。只改快捷方式自己记录的图标位置，不改目标程序、不移动文件、不影响分组归属；后缀不是 `.lnk` 的文件不会出现这两项。这一项改的是快捷方式本身，资源管理器里也会变；上一节的“更换显示图标…”只改栖桌内的显示。

实现走系统 `IShellLink` / `IPersistFile`（[code/src/ShortcutIcons.cs](code/src/ShortcutIcons.cs)），保存后用 `SHChangeNotify` 让资源管理器立即重绘，并丢弃本程序的图标缓存。`WScript.Shell` 无法把图标位置写空（会返回 E_INVALIDARG），因此清空恢复也走同一套接口。`code/src/tests/ShortcutIconTests.cs` 覆盖写入、读回、清空恢复，以及非快捷方式、缺失图标来源、负数序号的拒绝。

## 全盘快捷搜索与面板内重命名

`Ctrl＋Alt＋Space` 呼出简洁的圆角输入条，输入后展开带文件图标和图片缩略图的结果列表；再按一次或按 Esc 收起，点击其他窗口也会收起。在“文件搜索”设置可关闭快捷键，或添加“全盘搜索”桌面插件。两种入口共用搜索逻辑，显示 Everything 索引中的全部结果，不受桌面分区忽略规则影响。↑↓ 选择，Enter 打开，Ctrl＋Enter 在资源管理器定位；选中结果时按住 Ctrl 显示放大预览，图片显示缩略图，松开后收起。

优先使用可选的 Everything SDK 异步查询，缺失或不可用时尝试 ES 命令行；两者都不可用时明确显示“本机范围”，只搜索桌面与已连接项目，最多扫描 5000 项、4 层，不能视为全盘索引。开发目录会自动发现 `tools/Everything-1.4.1.1032.x86/Everything.exe` 便携版；其他位置可在设置中手动选择。“启动 / 检查 Everything 连接”会实际查询索引并反馈结果；仅检测到进程不代表 IPC 已连接。SDK 不随本轮构建新增打包，可放在程序目录或所选 Everything 程序同目录；开发目录也可使用已有 EverythingQuickSearch 参考项目的 DLL。高级搜索表达式由 Everything 提供。

桌面分区中文件右键“重命名”或选中文件后按 F2，直接编辑文件名。Enter 保存，Esc 取消；名称冲突等错误在文件名旁提示。已整理文件同时更新桌面恢复记录，重启可核对中断的重命名，撤销布局不会把真实文件引用恢复成旧名称。历史独立文件浏览窗口的重命名入口尚未全部改成就地编辑。

应用图标皮肤候选见 [开源应用图标皮肤调研](research/2026-10-17-开源应用图标皮肤调研.md)。现已提供 Fluent 应用、Papirus 应用两套本地测试皮肤，在“颜色和外观 → 应用图标皮肤 · 预览与一键切换”选择应用范围后即可应用或恢复系统图标。只改变栖桌内显示，未知应用保留原图，不改写快捷方式或程序文件。旧配置保持原皮肤；测试与覆盖范围见 [应用图标皮肤测试](research/2026-10-17-应用图标皮肤测试.md)。
